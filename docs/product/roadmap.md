# نقشه راه محصول (فازها)

> این سند، ترتیب ساخت محصول را تعیین میکند. هر فاز **فقط** پس از عبور از معیارهای خروج فاز قبلی
> شروع میشود، و هر فاز با **گزارش استاندارد مهندسی** تمام میشود.
> قواعد اجرا: [AGENTS.md](../../AGENTS.md) · گزارش: [.agents/rules/reporting.md](../../.agents/rules/reporting.md)

## اصول ثابت در همه فازها

| اصل | توضیح |
|---|---|
| فارسی کامل | هیچ متن انگلیسی برای کاربر نهایی. عدد فارسی، تاریخ جلالی، RTL. |
| وانیلا | HTML/CSS/JS وانیلا (`C-3`, `C-7`) · PHP خالص بدون فریمورک (`C-4`, `C-9`) |
| هاست اشتراکی | بدون daemon، بدون Redis، بدون Node در زمان اجرا (`C-8`) |
| پردازش سمت مرورگر | رندر، ترکیب ماکاپ، خروجی چاپ: کاملاً کلاینت (`C-6`) — [ADR-0001](../engineering/adr/ADR-0001-browser-side-design-engine.md) |
| اعتبار سمت سرور | هر مقدار مؤثر (قیمت، دسترسی، وضعیت سفارش) فقط از سرور |
| AI خاموش ولی آماده | دکمه غیرفعال + درز آماده اتصال (`C-12`, `C-13`) — [ADR-0003](../engineering/adr/ADR-0003-deferred-ai-provider-seam.md) |
| دو حالت کسبوکار | SaaS (خودکاربر) + B2B (حساب سازمانی) روی یک کدبیس (`C-14`) |
| دستور کار درگاه/پیامک | زرینپال برای پرداخت، کاوهنگار برای پیامک (`C-10`, `C-11`) — [ADR-0004](../engineering/adr/ADR-0004-iran-region-integrations.md) |

## وضعیت فعلی

| فاز | وضعیت | توضیح |
|---|---|---|
| ۰ | **در جریان — برش ۱ تحویل شد** | هسته درخواست/پاسخ، مسیریابی، مدیریت خطا، لاگ امن، اعتبارسنجی فارسی، ابزار self-check نصب، هارنس تست. باقی‌مانده: لایه پایگاه‌داده و مهاجرت، نصب‌کننده، نشست/CSRF/rate limit، صف کار و کران، سیستم طراحی RTL، رانبوک استقرار. |
| ۱ به بعد | شروع نشده | وابسته به تکمیل فاز ۰ |

> جزئیات و شواهد برش ۱ در [گزارش فاز ۰](../../docs/engineering/reports/2026-09-14-phase-0-slice-1-core.md).

## روش اجرا (هر فاز، بدون استثنا)

۱. سؤالهای باز همان فاز پاسخ داده شود (`O-n` در [project-context](../engineering/project-context.md))
۲. برنامه فاز نوشته و برای تأیید ارائه شود
۳. پیادهسازی افزایشی + تست همراه هر تغییر
۴. رفع خطاها با روش ریشهیابی (بدون وصلهی نشانه)
۵. بازبینی امنیت، کارایی، رگرسیون
۶. تأیید نهایی روی revision ثابت
۷. گزارش + ثبت در `docs/engineering/reports/`
۸. **توقف** و گرفتن تأیید شما برای شروع فاز بعد

## فاز ۰ — بنیان و اکتشاف (Bootstrap)

**هدف:** پیش از نوشتن فیچر، زمین را بسازیم: حقایق هاست، ساختار پروژه، لایهها، پایگاهداده، احراز هویت زیرساختی، تست، و رانبوک نصب.

| # | کار | خروجی |
|---|---|---|
| 0.1 | **گزارش توانمندی هاست** | اسکریپت `requirements` که نسخه PHP، افزونهها، موتور و نسخه پایگاهداده، cron، محدودیت حجم آپلود، دسترسی HTTP خروجی، SSL، دسترسی نوشتن را چاپ میکند → پر کردن `O-20`, `O-2`, `O-3` |
| 0.2 | ساختار پوشهها و front controller | یک نقطه ورود، مسیریابی بدون وابستگی، پشتیبانی از اجرا با و بدون `mod_rewrite` |
| 0.3 | هسته: پیکربندی، خطا، لاگ، JSON response | قالب پاسخ یکسان، مدیریت خطای مرکزی، correlation id، پیکربندی بیرون web root |
| 0.4 | لایه پایگاهداده و مهاجرت | اتصال، کوئری پارامتری، مهاجرت نسخهدار قابل اجرای مجدد (بدون shell) |
| 0.5 | اسکیمای هسته + seed | کاربر، نشست، تنظیمات، لاگ رویداد، صف کار |
| 0.6 | اعتبارسنجی و امنیت پایه | اعتبارسنج سمت سرور، هدرهای امنیتی، CSRF، rate limit مبتنی بر پایگاهداده، سیاست نشست/کوکی |
| 0.7 | صف کار + کران | job runner بچهمحدود، ایدمپوتنت، قابل اجرای مجدد، گارد قفل همزمانی |
| 0.8 | سیستم طراحی RTL | متغیرهای رنگ/فاصله، فونت فارسی self-host، اسکریپت پایه، کامپوننتهای پایه |
| 0.9 | هارنس تست | تست PHP سمت سرور + تست واحد JS سمت مرورگر + فیکسچرها (طبق تصمیم `O-11`) |
| 0.10 | رانبوک نصب و استقرار | نصب روی هاست تمیز، فقط با پنل، بدون shell. مستندشده و **اجرا شده** |

**معیار خروج:** نصب تازه روی هاست (یا محیط شبیهسازیشده) بالا میآید · مهاجرتها دو بار اجرا میشوند و خطا نمیدهند · کران یک job صف را دو بار اجرا میکند و حالت نهایی یکسان است · تستها واقعاً اجرا شدهاند و خروجی ثبت شده است · `O-20`, `O-2`, `O-3` پر شدهاند.

## فاز ۱ — موتور طراحی (قلب محصول)

**هدف:** رندر و ادیتور وانیلا + قرارداد سند طراحی + درز AI (خاموش).

| # | کار | خروجی |
|---|---|---|
| 1.1 | قرارداد سند طراحی | اسکیمای نسخهدار JSON + اعتبارسنجی سروری + مهاجرت نسخه |
| 1.2 | رندرر خالص | `render(document, profile)` با واحد مستقل از دستگاه (mm)، بدون وضعیت پنهان |
| 1.3 | لایهها | تصویر، متن فارسی (شکلدهی/RTL/ZWNJ)، ترتیب، شفافیت، قفل |
| 1.4 | تعامل | جابجایی، مقیاس، چرخش، برش، چسبیدن، راهنما، لمسمحور |
| 1.5 | Undo/Redo | تاریخچه محدود، پوشش همه اقدامها |
| 1.6 | ذخیره/بازیابی | پیشنویس محلی + ذخیره سروری، بدون از دست رفتن کار |
| 1.7 | آپلود دارایی | اعتبارسنجی دوطرفه (کلاینت + سرور)، انبار بیرون web root |
| 1.8 | خروجی چاپ | PNG/JPEG با DPI از قرارداد چاپ (`O-14`)، پیشرفت و امکان لغو |
| 1.9 | درز AI | پرچم سروری `ai.enabled=false`، اندپوینت capability، دکمه غیرفعال با توضیح فارسی، تست با provider جعلی |

**معیار خروج:** یک سند طراحی روی دو دستگاه/مرورگر خروجی یکسان میدهد · خروجی چاپ با نمونه واقعی چاپ مقایسه شده · پیشنویس پس از reload برمیگردد · درخواست مستقیم به اندپوینت AI رد میشود (نه فقط دکمه خاموش) · آزمونهای رگرسیون پیکسلی وجود دارد.

## فاز ۲ — استودیوی محصول: ماکاپ، رنگبندی، پیشنمایش

**هدف:** کاربر طرح را روی تیشرت/هودی ببیند و رنگها را تغییر دهد.

| # | کار | خروجی |
|---|---|---|
| 2.1 | مدل محصول و ماکاپ | نوع محصول، نماها (جلو/پشت/آستین)، ناحیه چاپ (`O-14`) |
| 2.2 | ترکیب روی ماکاپ | قرار دادن رندر طرح روی تصویر ماکاپ (کلاینت) |

**معیار خروج:** تغییر رنگ بدون بازگشت به سرور کار میکند · خروجی پیشنمایش با خروجی چاپ یک هندسه دارد (همان سند طراحی) · صفحه در ۳۲۰px تا دسکتاپ سالم است · تصاویر ماکاپ با فرمت/حجم بهینه و خودمیزبان.

## فاز ۳ — حساب کاربری، فروشگاه شخصی و لینک اشتراکی (SaaS)

**هدف:** کاربر ثبتنام کند، طرحش را ذخیره کند و لینک عمومی بگیرد.

| # | کار | خروجی |
|---|---|---|
| 3.1 | احراز هویت | موبایل + کد یکبارمصرف با کاوهنگار (`O-6`)، نشست امن، rate limit، خروجی OTP در صف |
| 3.2 | ورود مهمان → کاربر | طراحی مهمان در مرورگر حفظ شود و پس از ورود به حساب منتقل شود |
| 3.3 | طرحهای من | فهرست، جستوجو، تغییر نام، کپی، حذف (با تأیید) |
| 3.4 | انتشار طرح | ساخت محصول قابل فروش از طرح + وضعیت پیشنویس/منتشرشده |
| 3.5 | صفحه عمومی محصول | لینک اشتراکی، انتخاب رنگ/سایز، SEO پایه، متا فارسی، تصویر اشتراکگذاری |
| 3.6 | فروشگاه شخصی | صفحه سازنده، فهرست محصولات او، هویت بصری مینیمال |
| 3.7 | تنظیمات پروفایل | نام، تصویر، اطلاعات تماس، حذف حساب (`O-9`) |

**معیار خروج:** چرخه کامل مهمان→ثبتنام→ذخیره→لینک عمومی قابل انجام است · کد یکبارمصرف: منقضی، اشتباه، استفاده مجدد، برای شماره دیگر، سقف تلاش — همه تست شده · هیچ شمارهای قابل شمارش نباشد (enumeration) · صفحه عمومی در حالتهای خالی/خطا/۴۰۴ درست رفتار کند.

## فاز ۴ — سفارش و پرداخت (مسیر پول)

**هدف:** کاربر بخرد، زرینپال پرداخت کند، سفارش ثبت شود.

| # | کار | خروجی |
|---|---|---|
| 4.1 | مدل سفارش | سفارش، اقلام، قیمت اسنپشات، وضعیتها، شکل خرید (`O-18`) |
| 4.2 | محاسبه قیمت | فقط سمت سرور از دادههای خودمان (بدون اعتماد به کلاینت) |
| 4.3 | تراکنش پرداخت | ماشین حالت `initiated→pending→verified|failed|cancelled|refunded` + یکتایی + ایدمپوتنسی |
| 4.4 | زرینپال | درخواست پرداخت، هدایت، کالبک، **تأیید سمت سرور** و تطبیق مبلغ |
| 4.5 | تطبیق (Reconciliation) | job کرانی برای پرداختهای معلق؛ کالبک گمشده سفارش را خراب نکند |
| 4.6 | پیامک سفارش | قالبها و صف پیامک (تأیید سفارش، تغییر وضعیت) |
| 4.7 | پیگیری سفارش | صفحه «سفارشهای من»، وضعیتها به فارسی، صفحه تشکر |
| 4.8 | اطلاعات ارسال | آدرس، کدپستی، استان/شهر، اعتبارسنجی فرمت ایرانی (`O-13`) |

**معیار خروج:** تستهای پرداخت: کالبک تکراری، کالبک جعلی، مبلغ نامطابق، کالبک سفارش لغوشده، timeout درگاه، تطبیق پرداخت معلق — هیچکدام سفارش/اعتبار اضافه نسازند · یک تراکنش واقعی کممبلغ در سندباکس/واقعی ثبت شود · پیامک فقط از صف ارسال شود.
